# ADR-012 技術イベントは Doorkeeper の公開 API から取る

- 状態: 採用
- 日付: 2026-09-24
- 関連: ADR-008（テーマ単位収集とコスト制御）、ADR-010（プール探索エージェント）、ADR-011（補助金は API から取る）、Agent詳細要件定義書 §6.5 / §6.6 / §7.2 / §10.1

## 背景

補助金・アクセラ・共創を止めて、ハッカソンとビジコンだけにした（#65）。ところが
両方を合わせても、全国で 1 日数十件にしかならない。これだけ少ないと、プール探索
エージェントが解釈して絞り込み、採点する手応えが画面から感じられない。

ターゲットのエンジニアがいちばん多く参加するのは、勉強会・LT 会・もくもく会・
ハンズオン・カンファレンスといった技術イベントで、件数も桁違いに多い。これらは
connpass と Doorkeeper に集まっている。

- connpass の API（v2）は利用申請と API キーが要る
- Doorkeeper の API は認証なしで使える（5 分あたり 300 リクエストまで）

## 決定

### 決定1: 技術イベントは Doorkeeper の公開 API から作り、Grounding 検索を使わない

補助金（ADR-011）と同じ形にする。`CollectionTheme.source = "doorkeeper"` のテーマは、
検索・取得・抽出を飛ばす。検証・重複判定・保存は他のジャンルと同じ経路に乗せる。

| | Web 収集（ハッカソン・ビジコン） | 技術イベント |
| --- | --- | --- |
| 収集元 | Google Search Grounding → ページ取得 → 抽出 | Doorkeeper 公開 API（`GET /events`） |
| 検索代 | 1,000 クエリ 14 ドル | **ゼロ** |
| モデル呼び出し | 引用抽出で最大 15 回/Run | **ゼロ** |
| 開催日 | ページの行から読む | `starts_at` / `ends_at` |
| 申込締切 | ページの行から読む | **無い**（null のまま） |

テーマは次の 2 つで、どちらも全国を対象にする。地域は住所の都道府県で持ち、
地域での絞り込みは読み出し時に行う（`domain/regions.py`）。

- `meetup-study`：勉強会・もくもく会・ハンズオン
- `meetup-talk`：LT・Meetup・カンファレンス

キーワードごとに、45 日先までに始まるものを開催日順に最大 3 ページ（75 件）まで引く。
同じイベントは id で 1 件にまとめる。

### 決定2: 種別 `meetup` を足す

`EventKind` に `meetup` を足した（contracts が先）。表示名は「技術イベント」。

ページから抜き出す場合も、category が `meetup` / `conference` / `workshop` のものは
kind を `meetup` にした。これまではハッカソンとして扱っていたので、ハッカソンの
テーマの Run では、タイトルで技術イベントを名乗るページが対象から外れる。
ハッカソンと同じく、開催日が読めない技術イベントは載せない。

### 決定3: 申込締切は推測しない。検証の規則も変えない

Doorkeeper には申込締切にあたる項目が無い。多くは開催まで受け付けているが、
推測で埋めない（§6.5）。締切が無いので、検証の結果は `partial` のままにする
（§6.6、`validation_rule_version` は据え置き）。

画面では次のように扱う。

- 締切の行は「未確認」の代わりに「申込ページで確認」と出す。「締切なし」とは書かない
- 「要確認」の印とフィルタからは、欠けているのが締切だけの技術イベントを外す。
  そうしないと、一覧の大半に印が付いてノイズになる（#65 で補助金を止めたのと同じ理由）

### 決定4: 根拠は API の値、出典は organizer

根拠（§7.2）は、API が返した値を「項目名: 値」の形で持つ。引用元は Doorkeeper の
イベントページ（`public_url`）。

Doorkeeper のイベントページは、主催者が自分で書いて公開するページで、集約サイトの
転載ではない。そのため `sourceType` は `organizer` にする。ページを検索で拾った
場合は、これまでどおり `aggregator` 扱いのまま。

主催者名は `expand[]=group` で貰うグループ名にする。expand せずに id しか返らなかった
ときは、主催者を作らない（null）。

### 決定5: 外部入力として扱う

タイトル・会場・住所・説明は `prompt_guard.sanitize_free_text` を通し、長さを制限する。
説明の HTML はタグを外して要約に使うだけで、モデルには渡さない。公開 URL は
`https://` のものだけを使う。

呼び出しの間隔は 1.2 秒空け、1 クライアントあたり 60 回までにする。429 は間を置いて
2 回まで試し、それでも駄目なら諦める。

## 結果

- 1 日の収集は 12 タスク（ハッカソン 7、ビジコン 3、技術イベント 2）。Grounding 検索の
  回数は変わらない（40 回/日）
- デモとテストは `demo/meetups.py` の固定データを使い、ネットワークに出ない
- 評価データに `14-meetup-001`（締切あり → verified）と `14-meetup-002`（締切なし →
  partial）を足した

## 未確認のこと

- Doorkeeper の実際の応答は、開発環境のネットワーク制限のため、この変更の中では
  叩いて確かめていない。応答の形は公開ドキュメントに合わせた。本番の最初の収集で
  件数と主催者名が入っているかを確認する
- connpass は API キーが取れたら同じ形で足せる
