# ADR-007 実ページからの抽出（モデルは行を引用するだけ）

- 状態: 採用
- 日付: 2026-09-22
- 関連: Agent詳細要件定義書 §6.4（検索）・§6.5（抽出、年の推測禁止）・§7.5（confidence）・§8-2（集約サイトの下限）・§10.1 / §10.5（信頼できない入力）、ADR-004

## 背景

本番は `AGENT_DEMO_MODE=true` で動いており、検索は固定の結果、ページは同梱の
フィクスチャ、抽出が 0 件ならデモカタログで補っていた。実データを出すには
(1) Grounding 検索と実ページ取得を有効にし、(2) 実ページから日程を抽出できる
必要がある。

(1) は既に実装があり、`AGENT_DEMO_MODE=false` にすれば動く。問題は (2) で、
現在の抽出は「開催日: 2026年10月11日」のような行ラベルに依存しており、実ページの
多くはこの形をしていない。行ラベルで取れないページを捨てると一覧はほぼ空になり、
デモカタログで補うと「実データ」ではなくなる。

## 決定

### 決定1: モデルの役割は「該当行の引用」に限る

行ラベルで開催日が取れなかったページに限り、Gemini に次の JSON を返させる。

```
{"title", "eventDateLine", "deadlineLine", "venueLine", "organizerLine"}
```

各値は**ページ本文に一字一句そのまま現れる引用**でなければならない。返ってきた
引用は本文と照合し、無いものは捨てる（`_verbatim`）。日付・時刻・年を決めるのは
従来の `extraction/dates.py` のパーサで、モデルの出力から値を読むことはしない。
年の補完はページ全体の規則そのまま（本文に年が一つだけのときだけ）。
早割・作品提出などの締切行は従来と同じ除外表で落とす。

却下した案: モデルに構造化 JSON（ISO 日時）を直接出させる。§6.5 の「年を推測しない」
と §7.5 の「confidence はアプリ側算出」を守るには、モデルが値を作れない形にする
必要がある。引用に限れば、幻覚は照合で落ち、根拠（Evidence.excerpt）も引用そのものになる。

### 決定2: 防御は ADR-004 の3層をそのまま使う

本文は `wrap_untrusted`（`UNTRUSTED_PAGE`）で包み、システム命令は
`defended_system_prompt`（サンドイッチ + カナリア）。カナリアが漏れた応答は捨てる。
ページ内の命令は従来どおり観測のみ（`_note_injection_attempt`）で、抽出は続ける。
1 Run の呼び出し回数は `max_model_calls` の予算で頭打ちにし、予算切れは黙って諦める。

### 決定3: 実ページの出典種別は URL で決める

`extraction/sources.py`: 既知の集約サイト（connpass / doorkeeper / peatix / techplay /
eventbrite / meetup 等）は `aggregator`、それ以外は `official`。§8-2 の下限 0.60 は
この分類の上で効く。集約サイトだけが出典のイベントは `partial`（要確認）になる。

### 決定4: 本番はデモを完全に切る

`AGENT_DEMO_MODE=false` と `DEMO_CATALOG_FALLBACK=false`。抽出が 0 件なら 0 件と
出す。モデル ID は `GEMINI_MODEL` で差し替え可能（既定 `gemini-3.8-flash`）。
最新モデルは `global` エンドポイントにしか無いので、Gemini の呼び出し先は
Cloud Run のリージョンと分けて `GEMINI_LOCATION`（既定 `global`）で持つ。

### 決定5: 検索は期間とドメインで絞り、イベントサイトを指名する

Google Search ツールの `time_range_filter`（直近 180 日）と `exclude_domains`
（まとめ記事の基盤）を使う。どちらも検索側のフィルタで、モデル呼び出しは増えない。
クエリは一般検索 1 本と、connpass / Peatix / Doorkeeper・TECH PLAY を `site:` で
指名した 3 本。告知ページはこれらに集まっており、一般検索ではまとめ記事に押される。
`site:` は Grounding では厳密には効かないことがある（他ホストも混ざる）。

### 決定6: 引用の抽出は思考を切り、検索・取得・抽出は並列にする

3.x 系は思考が入ると 1 ページの引用に数分かかる。引用は推論の要らない作業なので
`thinking_budget=0` にし、1 呼び出しの上限を 60 秒にする。SDK の同期 API は
event loop を塞ぐので `aio` を使い、検索（4 本）・ページ取得（同時 6）・
引用（同時 4）を並列にした。これで 1 Run が 90 秒前後（§11.1 の p95 120 秒内）。

### 検討した案: langextract

Google の langextract は「引用を文字位置で本文に結び付ける」抽出ライブラリで、
狙いは決定1と同じ。今回は自前の照合（`_verbatim`）で同じ保証が得られており、
依存と独自のプロンプト形式を増やす理由が無いので採用しない。精度が足りない
ことが分かったら、少数事例（few-shot）の仕組みを持つ langextract へ寄せる。

### 決定7: 一覧の各行に根拠を添える

`GET /api/events` が各イベントに `evidencePreview`（出典 URL・種別・引用、
締切 → 開催日 → タイトルの順で最大 4 件）を添える。保存はせず応答時に付ける。
一覧の行では締切と開催日の根拠を 2 件まで見せ、全文は詳細で読む。

## 検証

- Vertex AI（`global` / `gemini-3.8-flash`）で実行: 「生成AI ハッカソン / 大阪・関西」で
  4 クエリ → 候補 7 → 要確認 5（締切が本文に無いものは `partial`）、92 秒、モデル呼び出し 13 回。
  抽出された開催日はすべて本文の引用（例: 「9/24 ~ 9/26 開催」「2026年10月24日(土)にキックオフイベントを開催します」）に裏付けられている
- `tests/test_model_locator.py`: 引用が本文にあれば候補になる／本文に無い締切は捨てる／
  早割は締切にしない／年が確定しない引用は候補にしない／非 JSON・カナリア漏れは捨てる
- 評価ハーネスはデモモードで動くのでモデル経路を通らない。抽出・検証のルールと
  `validation_rule_version` は不変で、`./scripts/run-evals.sh` は従来どおり通る

## 限界

- 本文の先頭 12,000 文字だけをモデルに渡す。日程が後半にある長いページは取れない
- 出典種別の URL 判定は表に依る。表に無い集約サイトは `official` 扱いになる
- モデルの引用が本文と空白以外で食い違うと（全角/半角の混在など）照合で落ちる。
  NFKC 正規化は両側に掛けているが、それでも取りこぼす分は `partial` にも `verified` にもならず、単に一覧に出ない
