# ADR-011 補助金は Web 収集ではなく jGrants の公開 API から取る

- 状態: 採用
- 日付: 2026-09-22
- 関連: ジャンル拡張計画 段階4、ADR-007（モデルは引用するだけ）、ADR-008（テーマ単位収集とコスト制御）、Agent詳細要件定義書 §6.5 / §6.6 / §7.2 / §10.1

## 背景

ジャンルを広げる順番として、展示会（段階3）より補助金（段階4）を先にやることにした。
展示会は実ページを調べた結果、**民間の大型展示会が出展申込の締切を公開していない**
（会期と「出展検討資料ダウンロード」しか無い）。締切と実施日を分けて見せるのが
このプロダクトの核なので、締切が公開されないジャンルは相性が悪い。

補助金はその逆で、デジタル庁の jGrants が公開 API で構造化データを配っている。
Web を検索して本文から読む必要がない。

## 決定

### 決定1: 補助金は jGrants の公開 API から作り、Grounding 検索を使わない

`CollectionTheme.source` を足し、`"jgrants"` のテーマは検索・取得・抽出を飛ばす。
検証・重複判定・保存・フィードへの投稿は他のジャンルと同じ経路に乗せる。

| | Web 収集（ハッカソン〜共創） | 補助金 |
| --- | --- | --- |
| 収集元 | Google Search Grounding → ページ取得 → 抽出 | jGrants 公開 API |
| 検索代 | 1,000 クエリ 14 ドル | **ゼロ** |
| モデル呼び出し | 引用抽出で最大 15 回/Run | **ゼロ** |
| 締切 | ページの行から読む（外すことがある） | `acceptance_end_datetime` |

テーマは `subsidy-startup` / `subsidy-dx` / `subsidy-monozukuri` / `subsidy-kansai` の 4 つ。
API は `keyword` 必須（2 文字以上）で「全件ください」ができないので、テーマごとに
キーワードを巡回する。地域テーマは `target_area_search` で絞る（`全国` は残す）。

### 決定2: API の作法に合わせて呼び出しを抑える

レート制限がある（実測で 150ms 間隔でも 500 リクエストあたりで 429）。

- 呼び出しの間隔を 250ms 空ける
- 1 クライアントあたりの呼び出し上限を持つ（既定 40）。超えたら黙って打ち切る
- 一覧はキーワードごとに 1 回。詳細（`/exp/v2/public/subsidies/id/{id}`）は
  **締切が近い順に 20 件まで**。詳細が取れなかったものは一覧の値だけで載せる
- 429 は数回だけ待って再試行し、駄目なら次へ。1 テーマの失敗で Run を落とさない

### 決定3: 日時は UTC で返るので JST に直す。読めない値は締切なしにする

`acceptance_end_datetime` は `2026-10-30T14:59:00.000Z`（= JST 23:59）。
ここを取り違えると締切が 1 日ずれる。読めない値のときは None にし、
締切を推測で作らない（§6.5）。**締切が読めない補助金は載せない**。

### 決定4: 実施日は持たない。「未確認」ではなく「なし」と出す

補助金に会場へ集まる日は無い。`dates.eventStart` は null のまま（段階1 で任意化済み）。
UI は kind が subsidy のとき実施日を「なし」と出し、間隔の行には
「補助金に実施日はありません。締切までに申請します。」と書く。
「未確認」と出すと、探し損ねたように見えてしまう。

補助率・上限額・対象地域・従業員数・利用目的・対象業種は `attributes` に
API の値のまま入れる（段階2 の仕組み）。受付開始日は `milestones` に持つ。

### 決定5: 根拠は API の値そのもの。出典は jGrants の公開ページ

`Evidence.excerpt` にはページ本文の引用ではなく、`title: …` や
`acceptance_end_datetime: …` のように**項目名と値**を書く。`sourceUrl` は詳細 API が
返す `front_subsidy_detail_page_url`（無ければ `https://www.jgrants-portal.go.jp/subsidy/{id}`）。
これで §7.2 の「値がどこから来たか」を後から突き合わせられる。

### 決定6: 返ってくる文字列は外部入力として扱う

タイトルも属性も `sanitize_free_text` を通す（§10.1）。詳細 API の `detail` は
リッチテキスト由来の HTML で、モデルに渡す用途も表示する用途も無いので**持たない**。

## 影響

- テーマは 17 に増える（Cloud Run Job の `--tasks 17`）。補助金 4 テーマは検索を
  使わないので、`DAILY_GROUNDING_CAP` は 90 のまま据え置き
- デモ・テスト・評価ではネットワークに出ない（`demo/subsidies.py` の固定データ）。
  差し替えは `set_subsidy_source`

## 確認

- 2026-09-22 に一覧・詳細の両 API を実際に呼び、項目名と値を確認した
