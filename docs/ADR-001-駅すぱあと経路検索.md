# ADR-001: 駅すぱあと API によるイベント会場までの経路検索

日付: 2026-09-19  
状態: 採用

## 背景

イベント一覧では「申込締切」と「開催日」を分けて提示しているが、会場開催のイベントでは
「開始時刻に間に合うにはいつ出発すべきか」が参加判断に直結する。
駅すぱあと API（Val Laboratory）のアクセスキーが提供されたため、経路検索を組み込む。

## 決定

- **REST API を Python バックエンドから直接呼ぶ**（`services/agent/src/event_agent/ekispert.py`）。
  MCP サーバー（`https://api-mcp.ekispert.jp/mcp`）は使わない。理由: 経路検索は決定的な処理であり、
  LLM のツール呼び出しを介す必要がない。キーはサーバー側にのみ置き、フロントには渡さない。
- 使用エンドポイントは 2 つに限定する（このキーで利用可能な機能の範囲内）。
  - `GET /v1/json/station/light?name=&type=train` — 駅名 → 駅コード
  - `GET /v1/json/search/course/extreme?viaList=&date=&time=&searchType=arrival&answerCount=1`
    — イベント開始時刻（JST）に到着する経路を 1 件
- API 契約: `GET /api/events/{eventId}/route?from=<出発駅名>` → `EventRouteResponse`
  （`packages/contracts/schemas/route.json`）。
- 到着駅は `Event.location.nearestStation`（契約に追加）を使い、無ければ `region` にフォールバックする。
  最寄駅はソースから取得した値のみ設定し、推測しない（未設定なら 400 を返す）。
- `EKISPERT_API_KEY` 未設定時は 503 を返し、UI は経路パネルにエラー文言を表示する。

## 制約・対策

- **秘密情報**: キーは環境変数 `EKISPERT_API_KEY`（Cloud Run には GitHub Secret 経由）。
  httpx がクエリ文字列付き URL を INFO でログ出力するため、`httpx` ロガーは WARNING に下げる。
- **SSRF**: 接続先は `api.ekispert.jp` 固定。ユーザー入力は駅名（40 文字以内）のみで、URL 生成には使わない。
- **課金**: アクセスキー単位で従量課金されるため、駅名・経路の結果を 30 分間メモリキャッシュする。
- **時刻**: 経路探索は JST 前提。デモカタログの日時も JST（`+09:00`）で保持するよう修正した。

## 今後

- 収集ワークフローの抽出ステップで「最寄駅」を根拠付きで抽出する（現状はデモカタログのみ設定）。
- 複数経路（`answerCount>1`）や出発時刻指定は、要件が固まってから追加する。
