# **イベント自律管理AIエージェント「超イベント管理（仮称）」要件定義書**

## **1\. プロジェクト概要・背景**

### **1.1 背景**

エンジニアやクリエイター向けイベント（ハッカソン、カンファレンス、展示会、アクセラレーター選考、ポップアップなど）は情報が各プラットフォームに散在しており、以下の運用上の課題が存在する。

* **2つの日程の混同**: 「申込締切日」と「イベント開催日」が異なり、締切を見落として参加機会を逃す。  
* **情報収集・選定の負荷**: 自身の関心分野に合致したイベントを探し出し、場所・日時・申込URLを抽出・精査する手間が大きい。  
* **スケジュール反映の二度手間**: カレンダーへの転記作業が手動で行われている。

### **1.2 目的**

ユーザーがあらかじめ設定した「関心領域（プロンプトベース）」に基づき、AIエージェントがWeb上のイベント情報を自律的に収集・整理。**「申込締切」と「開催日」を明確に分離した直感的なカレンダーUI**で提示し、ワンクリックでGoogle カレンダーに同期できるウェブアプリケーションを提供する。

## **2\. ユーザー像と解決する課題**

### **2.1 ターゲットユーザー**

* 技術トレンドを追うエンジニア、ハッカソン参加者、起業準備者、登壇機会を探すスピーカー。

### **2.2 主要な解決課題**

1. **締切忘れ防止**: 申込期日と開催日を分離して可視化し、リマインドを容易にする。  
2. **収集・整理の自動化**: 単なるキーワード検索にとどまらず、エージェントが開催年（2026年等）や条件を特定・検証して提示する。  
3. **カレンダー同期のシームレス化**: Google Calendar APIと連携し、クリック1回で双方の日程を適切に登録可能にする。

## **3\. システムアーキテクチャ（GCP構成）**

ハッカソンスライドの推奨パターン（**01: 独自のUIが必要なアプリ**）に準拠した構成とする。

\[ ブラウザ / Web UI (React / Next.js) \]  
                │  
                ▼ (HTTPS)  
      \[ Cloud Run \]  
  (UIホスティング \+ バックエンドAPI \+ Agent実行環境)  
        │                 │                 │  
        ▼                 ▼                 ▼  
  \[ Vertex AI \]     \[ Cloud Firestore \]   \[ 外部API \]  
 (Gemini 2.0 Flash)    (ユーザー・イベント情報)  \- Google Calendar API  
                                          \- Web Search / Scraper

| レイヤー | 採用技術・サービス | 役割・選定理由 |
| :---- | :---- | :---- |
| **フロントエンド & API** | **Cloud Run** (Next.js / FastAPI等) | UIホスティングとエージェントAPIロジックを統合したコンテナ実行環境。スケーラビリティと高速デプロイを両立。 |
| **LLM / AIエージェント** | **Gemini 2.0 Flash** (Vertex AI / Google AI Studio) | 複数ステップの自律実行、Web検索グラウンディング、イベント詳細（日時・場所・URL・締切）の構造化抽出。 |
| **データベース** | **Cloud Firestore** | サーバーレスNoSQL。ユーザー設定（関心プロンプト）、検出済みイベント、カレンダー連携ステータスを管理。 |
| **外部連携** | **Google Calendar API** | OAuth 2.0認証を通じた予定の登録・同期。 |
| **認証** | **Firebase Authentication** / Google Identity Platform | Googleアカウントによるシングルサインオン（Googleカレンダー連携のスコープ含む）。 |

## **4\. 機能要件**

### **4.1 エージェント自律タスクフロー**

AIエージェントは単発のチャット応答ではなく、以下のマルチステップを自律実行する。

1. **条件絞り込み＆収集**:  
   * ユーザーの「関心プロンプト（例: ハッカソン、GCP、生成AI）」および指定年度（例: 2026年）に基づき検索を実行。  
2. **情報特定・パース（構造化）**:  
   * 抽出データ: イベント名, 概要, 開催日時, 申込締切日時, 開催場所（オンライン/会場）, 公式/申込URL。  
   * 申込期間と開催日を明確に分離して認識。  
3. **データ検証＆重複排除**:  
   * 過去に提示済み、または終了したイベントの除外。  
4. **UI反映＆カレンダー同期**:  
   * レコメンデーション理由を添えてダッシュボードに一覧表示。

### **4.2 コア機能一覧**

| ID | 機能名 | 詳細説明 |
| :---- | :---- | :---- |
| **F-01** | プロンプトベースの関心設定 | 自然言語で自身の興味・関心（職種、技術分野、地域、オンライン可否など）を登録・更新できる。 |
| **F-02** | エージェント自律収集 & 更新 | 「イベントを更新」ボタン押下、または毎朝の定期実行により、Webから最新イベントを探索・構造化抽出する。 |
| **F-03** | 2軸カレンダー / リスト表示 | 認知負荷を低減するため、\*\*「申込締切」**と**「イベント実施日」\*\*を色分けまたは別軸バッジで表示する。 |
| **F-04** | Google カレンダーワンクリック追加 | ユーザーが選択したイベントの「申込締切（リマインダー）」および「実施日程」をカレンダーに即座に登録。 |
| **F-05** | イベント選定・ブックマーク | 提案されたイベント群から、興味のあるものをチェック・キープできる。 |
| **F-06** | 主催者投稿フィード | 主催者が告知文を投稿でき、ユーザーは AI 収集結果とは別のフィードとして眺められる。本文から「申込締切」「開催日」を決定論的に抽出して F-03 の2軸表示と F-04 のカレンダー登録に接続し、AI 収集イベントと同じものは結び付けて表示する。固定／優先表示の枠をデータモデルとして持つ（課金は対象外）。詳細は ADR-006。 |

## **5\. UI/UX要件（認知負荷低減の工夫）**

手書きメモにある「申込期間と実施日の混同防止」「直感的な選定」を実現する専用レイアウト。

1. **デュアルタイムライン表示**:  
   * 各イベントカードに「🚨 申込期限: ○月○日」と「📅 実施日: ○月○日」を明確な視覚的差別化（タグ・色分け）をつけて表示。  
2. **ワンクリック同期アクション**:  
   * 「申込締切を登録」「本番日程を登録」「両方まとめて登録」のトグル/アクションボタンを用意。  
3. **ステータスバッジ**:  
   * 「未登録」「カレンダー登録済み」「締切間近」のステータスを即座に視認可能にする。

## **7\. 将来的な拡張性（アイデアメモより）**

1. **MCP（Model Context Protocol）連携**:  
   * 参加可否の確認メールやSlack通知から、参加確定情報を自動取得してカレンダー更新を行う。  
2. **開発者向けイベントPR機能（マネタイズモデル）**:  
   * イベント主催者向けに、特定関心を持つユーザーのフィード上部にスポンサー枠として掲載できるプロモーションモデルの導入。
