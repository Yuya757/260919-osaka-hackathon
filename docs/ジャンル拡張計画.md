| 項目 | 内容 |
| --- | --- |
| 版 | 0.1.0（2026-09-22 起票） |
| 状態 | 計画。着手前 |
| 関連 | ADR-008（テーマ単位収集）、ADR-010（プール探索）、ADR-006（主催者投稿）、ADR-009（計測）、要件定義書 §4.2 |

## なぜ広げるのか

ハッカソンに絞って形は整った（テーマ単位のバッチ収集 → 共有プール → プール探索
エージェント）。同じ仕組みは「締切があり、公開Webで告知され、見逃すと終わる」
機会すべてに効く。ユーザー（エンジニア、起業準備者）にとって、ハッカソンと
ビジコンとアクセラは**同じ判断軸で並ぶべきもの**である。

## 拡張しても変えないこと

- 申込締切と実施日を分けて出す（上位§5-1）
- 根拠のない値を採用しない。年・締切・日付を推測しない（§6.5）
- 収集はテーマ単位のバッチ、ユーザー向けは検索なしのプール探索（ADR-008 / ADR-010）
- 主催者投稿と計測の仕組み（ADR-006 / ADR-009）

## ベクトル化（Embedding）を今は入れない理由

ジャンルは**属性で切れる**。「ビジコンだけ」「大阪の補助金」は `kind` と地域の
決定論フィルタで足り、ベクトルの出番はない。ベクトルが効くのは同じジャンルの中で
「ヘルスケア領域のアクセラ」「製造業向けの共創」のようにテーマの言い換えが要る
ときで、それはプールが数百件・ジャンル内で絞っても数十件残る規模になってからである。

コストの面でも動機は薄い。「探す」1 回は Gemini 2 呼び出しで ≒0.6 円、費用の主は
Grounding 検索（バッチ側に隔離済み）で、embedding はそこに触れない。

**再検討の条件**: 1 ジャンル内のプールが 50 件を超え、語の一致では上位 20 件の
足切りが実害を出すようになったとき。そのときは「収集時に埋め込みを保存 →
決定論スコアとコサインで全件を並べ、モデルは上位 5 件の理由だけ」を足す。

## 本当の課題は「構造が違う」こと

現在の `Event` は `eventStart` 必須で、「申込締切 → 開催日」の 2 軸を前提にしている。

| ジャンル | 締切 | 実施 | 固有の属性 | 2軸に乗るか |
| --- | --- | --- | --- | --- |
| ハッカソン | 申込締切 | 開催日 | テーマ、形式 | ○ |
| ビジコン | 応募締切 | 一次審査 / 最終審査・発表日 | 賞金、対象（学生/法人）、応募形式 | ○（実施 = 最終審査日） |
| アクセラ | 募集締切 | プログラム期間、Demo Day | 出資の有無、期間、対象ステージ | △（実施が期間） |
| 共創・オープンイノベーション | 公募締切 | 採択後の協業期間 | 募集企業、募集テーマ | △（実施が期間） |
| 展示会 | 出展申込締切 / 来場登録締切 | 会期 | 出展料、出展 or 来場 | △（締切が 2 種類） |
| 補助金 | 公募締切 | **無い**（事業実施期間） | 補助率、上限額、対象者、対象地域 | ✗ |

## 段階と順序

構造がハッカソンに近い順に広げる。各段階は独立してデプロイでき、前の段階を壊さない。

### 段階1: `kind` を導入する（ビジコンを同時に載せる）

> 事前調査（下記）の結果、`eventStart` の任意化・`milestones`・ラベル表のジャンル別化を
> 段階1 に前倒しした。これらを後回しにするとビジコンが 1 件も載らない。

- 契約 `event.json`: `kind`（`hackathon | contest | accelerator | cocreation | exhibition | subsidy`）を追加。既存の `category` は表示用の細分として残すが、絞り込みは `kind` で行う
- **`eventStart` を任意にする**（`kind != "hackathon"` で実施日が無い告知がある）。2 軸表示は実施日が無ければ「締切のみ」を出す
- **`dates.milestones`**（`{label, at, precision}` 最大 5）を足し、エントリー開始 / 一次選考発表 / 最終審査会 / 結果発表 を落とさずに持つ
- **ラベル表を `kind` ごとに**持つ（`workflows/themes.py` の各テーマに `deadline_labels` / `exclude_labels` / `milestone_labels`）。「提出締切」はハッカソンでは除外、ビジコンでは採用
- 締切のラベル行が範囲（「募集期間 A〜B締切」）のときは `parse_range` の **end** を締切にする
- 抽出: `extractor._CATEGORY_WORDS` を `kind` 判定に拡張（`ビジネスコンテスト`/`ビジコン`/`アイデアコンテスト` → contest）。ラベル表 `APPLICATION_LABELS` に `応募締切`（既にある）、`エントリー締切`（既にある）を確認し、`一次審査` `最終審査` `結果発表` を `EVENT_DATE_LABELS` とは別の「マイルストーン」として扱うかを決める（段階2）
- テーマ: `kind × 地域` に一般化。まず `contest-kansai` / `contest-kanto` / `contest-online` を足す（7 テーマ × 4 クエリ = 28 検索/日、`DAILY_GROUNDING_CAP` を 40 → 60）
- プール探索: 解釈に `kinds`（配列）を足し、「ビジコン」「コンテスト」→ contest。絞り込みは決定論
- UI: チップに ジャンル（すべて / ハッカソン / ビジコン）を足す。行に `kind` のラベル
- 評価: `evals/cases/12-contest-*.json` を 5 件（応募締切と審査日、賞金の記述、学生限定）

### 段階2: 実施が「期間」のジャンル（アクセラ・共創）

- `milestones` は段階1 で入る。ここでは「Demo Day」「採択発表」「プログラム期間」の語彙を足す
- `attributes`（`Record<string, string>`、最大 10、各 60 字）を足し、ジャンル固有の値（賞金、出資、対象ステージ、募集企業）を表示と絞り込みに使う。**構造化はしない**（ジャンルごとにスキーマを分けると契約が増えすぎる）
- 抽出: `milestones` は既存の `find_labelled` + `parse_date` で拾える。ラベル表をジャンル別に持つ（`workflows/themes.py` の各テーマに `deadline_labels` / `milestone_labels` を持たせる）
- プール探索: 「締切が近い順」だけでなく「実施が近い順」で並べられるようにする

### 段階3: 展示会（締切が 2 種類）

- `dates.applicationDeadline` は**出展申込締切**、来場登録の締切は `milestones` に `来場登録締切` として持つ
- `attributes` に `出展料` `来場無料` `主催者`。UI は「出展したい / 見に行きたい」でフィルタ（`attributes` の有無で決定論的に）
- 会期は `eventStart` 〜 `eventEnd` にそのまま乗る

### 段階4: 補助金（別モデル）

- **Web 収集ではなく jGrants の公開 API から取る**（デジタル庁、構造化データ）。スクレイピングと LLM 抽出が不要になり、精度が桁違いに上がる。`clients/jgrants.py` を足し、テーマ `subsidy-*` はこのクライアントを使う（Grounding 検索は使わない = 検索代ゼロ）
- 契約: `eventStart` の任意化は段階1 で済んでいる。補助金は常に実施日なしで、代わりに `attributes` に `事業実施期間` `補助率` `上限額` `対象者` `対象地域`
- 2 軸表示は「公募締切 → 事業実施期間」。実施日が無いので「開催日」ラベルを `kind` で切り替える
- 影響が大きいので ADR を 1 本書く（ADR-011 想定）

## 決めていないこと

- `attributes` の値をどこまで抽出するか（モデルに引用させるか、ラベル表で拾うか）。
  ADR-007 の「モデルは引用するだけ」を守るなら後者が素直
- ジャンルをまたぐ推薦の重み（ビジコンとハッカソンを同じ土俵で並べるか、ジャンル別に見せるか）
- 主催者投稿のジャンル指定（投稿フォームに `kind` を足すか、本文から判定するか）

## 事前調査: ビジコンの告知ページを読む（2026-09-22 実施）

段階1 に着手する前に、実際のビジコン告知ページを**現在のパイプラインに通して**
何が取れて何が落ちるかを確かめた。Grounding 検索 3 本 → 取得 → 行ラベル抽出 /
引用抽出（ADR-007）の順に実データで確認した。

読んだページ: 日本政策金融公庫「高校生ビジネスプラン・グランプリ」（2 サイト）、
大阪市のビジネスプランコンテスト、学生向けビジコンのまとめ記事。

### 結果: 現在の行ラベル抽出はビジコンではほぼ機能しない

4 ページ中、開催日 0 件、申込締切 1 件（しかもまとめ記事からの誤検出）。

原因は**ラベルと値が別の行にある**こと。告知ページは表組みで、`to_text` が
見出しセルと値セルを別々の行にするため、同一行を前提とする `find_labelled` が
当たらない。順序も一定しない。

```
[18] 'エントリー開始'        ← ラベル行
     '2026年8月19日'         ← 値は次の行
[20] 'エントリー締切'
     '2026年9月24日'
[35] '締切'
     '2026年09月24日 (木)'
     'ビジネスプランシート応募・提出締切、必着'   ← 値の後にラベルが来ることもある
```

### 引用抽出（ADR-007）は正しく取れる

モデルに該当行を引用させると、同じページから次が取れた。

| 項目 | 引用 |
| --- | --- |
| タイトル | 第 14 回「創造力、無限大∞ 高校生ビジネスプラン・グランプリ」 |
| 開催（最終審査会） | 2027年1月10日 |
| 締切（エントリー） | 2026年9月24日 |
| 会場 | 場所: オンライン / 東京大学 伊藤謝恩ホール |
| 主催 | 日本政策金融公庫 |

パーサ側も、これらの引用（改行を含むものも）を正しく日付にできることを確認した。
「2026年11月下旬」「2026年10月~11月」は日が無いので `None`（推測しないので正しい）。

→ **ビジコンでは引用抽出が主経路になる**。現在の実装は「行ラベルで開催日が取れな
かったページだけモデルに回す」ので分岐の変更は要らないが、**1 ページ 1 呼び出し**に
なるため、テーマあたりの呼び出し予算（`max_model_calls=15`）に収まるか要確認。

### 見つかった不具合（段階1 で直す）

1. **「提出締切」が除外語に入っている**。`NON_APPLICATION_DEADLINE_LABELS` は
   ハッカソンの「作品提出締切」を想定した除外だが、ビジコンでは
   「ビジネスプランシート応募・提出締切、必着」が**本物の応募締切**である。
   現在はこの行が捨てられる。→ 除外語を `kind` ごとに分ける必要がある
   （計画書で段階2 に置いた「ラベル表のジャンル別化」は**段階1 で必要**）
2. **「募集期間 A〜B締切」から開始日を締切として拾う**。
   「プラン募集期間 2026年6月4日(木)~2026年8月6日(木)13:00締切」に対し
   `find_application_deadline` は `parse_date`（= 6/4）を返す。締切として採るべきは
   範囲の**終わり**（8/6）。→ 締切のラベル行が範囲のときは `parse_range` の end を使う

### 設計への影響（計画の修正）

1. **`eventStart` 必須の壁は段階1 で来る**。ビジコンには「締切はあるが実施日が
   無い／曖昧（結果発表は11月下旬）」が普通にある。現在の `candidate_from_lines` は
   開催日が取れないと候補にしないので、そのままでは**締切だけが分かっている
   ビジコンを全部落とす**。段階4（補助金）に置いた「`eventStart` 任意化」を段階1 に
   前倒しし、`kind == "contest"` でも実施日なしを許す
2. **`milestones` も段階1 で要る**。ビジコンの時系列は「エントリー開始 → 締切 →
   一次選考通過発表 → 最終審査会 → 結果発表」で、2 軸（締切 / 実施）に潰すと
   情報が落ちる。2 軸表示は「エントリー締切 → 最終審査会」に当て、残りを
   `milestones` に持つ
3. **まとめ記事サイトの追加**。`startuplist.jp`（「学生向けビジコン13本」の記事）が
   `ARTICLE_HOSTS` に無いため候補になり、記事中の日付を誤って締切にした。
   `compe.japandesign.ne.jp` は個別コンペのページなので記事ではないが、
   コンペ情報の集約サイトなので `aggregator` に分類すべき（現在 `official` 判定）
4. **年が複数あるページが普通**（2025 / 2026 / 2027 が同一ページに出る）。
   `fallback_year` は使えないが、引用抽出は年入りの行を返すので実害はない

### 収集した語彙（ラベル表の素案、contest）

- 締切: エントリー締切、応募締切、募集締切、提出締切、応募・提出締切、必着、申込期限
- 開始: エントリー開始、募集開始、受付開始
- マイルストーン: 書類選考結果通知、一次選考通過（発表）、プレゼン審査、
  二次審査、最終審査会、結果発表、表彰式、集合研修
- 除外（contest では締切ではない）: 説明会、事前相談、質問受付
