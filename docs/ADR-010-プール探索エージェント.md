# ADR-010 プール探索エージェント

- 状態: 採用
- 日付: 2026-09-22
- 関連: Agent詳細要件定義書 §6.8（推薦）・§3.7 / §6.4（Search Suggestions）・§10.5（信頼できない入力）、ADR-004、ADR-008

## 背景

ADR-008 で Web からの収集はテーマ単位のバッチになった。残っていたのは、ユーザーが
「探す」を押したときに何をするかである。従来は Grounding 検索（Web に出る）を
起動していたが、検索代がユーザー数に比例するので本番では止めたい。一方、
キーワード一致の並べ替えだけでは「京都で来月の学生向け生成AIハッカソン」のような
問いかけに応えられず、エージェントらしさも無い。

## 決定

### 決定1: 「探す」= バッチ収集済みのプールを探すエージェント。Web には出ない

`POST /api/pool-search {query, sessionId?}`。4 つの役割で進め、それぞれの行動を
`activity[]` で返す（UI の 4 役割パネル）。

| 役割 | 何をするか | モデル |
| --- | --- | --- |
| 解釈 | 問いかけを `SearchIntent`（関心・地域・オンライン・開催期間・語・**種別**）に構造化 | 1 回 |
| 絞り込み | **種別** / 地域 / オンライン / 開催期間で決定論的に絞る | 無し |
| 採点 | §6.8 の決定論スコアに、上位 20 件へのモデルの関連度（0-100）と一言の理由を合成 | 1 回 |
| 提示 | 並べて返し、関心条件をセッションに残す | 無し |

1 回の「探す」で Gemini 2 呼び出し、検索代ゼロ。本番の `MANUAL_RUNS_ENABLED` は
false にし、Grounding 探索（`POST /api/agent-runs`）は管理者向けの裏口として残す。

### 決定2: モデルの出力は検証してから使い、候補の事実は書かせない

- 解釈: 地域は既知の選択肢（関西/大阪/京都/…/オンライン）に無いものを捨てる。日付は
  ISO 形式でなければ捨てる。語は `sanitize_free_text` を通す。読めない応答や
  カナリア漏れは規則ベースの解釈（「来月」「10月」「今週末」の決定論的な期間化、
  地名の一致）に落とす
- 採点: 返せるのは候補 id・関連度・40 文字以内の理由だけ。id が候補に無いもの、
  関連度が数値でないものは無視。理由は候補に書かれた事実に基づくよう指示するが、
  日程や場所の**値**はモデルの出力から一切読まない（表示は保存済みの Event から）
- 問いかけは `UNTRUSTED_USER_MESSAGE`、候補一覧は `UNTRUSTED_CANDIDATES` で包み、
  システム命令は防御付き。命令様の問いかけは発話と同じく拒む（ADR-004）

### 決定2-2: 種別は語の表から決め、モデルの値は列挙で検証する

ジャンルを広げるとプールにハッカソンとビジコンが混ざる（ジャンル拡張計画 段階1）。
「ビジコン」と聞かれてハッカソンを並べては答えになっていないので、`SearchIntent`
に `kinds` を足し、一致したときだけ種別で絞る。

- 語の表（「ビジコン」「ビジネスプランコンテスト」「グランプリ」→ contest、
  「アクセラ」→ accelerator …）で規則的に決める。モデルにも `kinds` を返させるが、
  `EventKind` の列挙に無い値は捨て、空なら規則の結果を使う
- **種別に触れていない問いかけでは絞らない**。「京都で来月 学生向け 生成AI」は
  ジャンルを問うていないので、全種別を採点順に返す
- 一覧のジャンルチップは解釈結果に追従する。絞り込まれている理由が画面に残るため

### 決定3: Search Suggestions の表示義務は生じない

一覧の上に出す一言（`reply`）とモデルの理由は Grounding を経ない生成文なので、
§3.7 / §6.4 の表示義務は無い。一覧の Search Suggestions 枠は外した。Grounding の
生成文を画面に出す箇所が再びできたら、そのとき戻す。

### 決定4: 一覧の絞り込みは問いかけの解釈に任せる

入力欄の文字での即時絞り込み（語をすべて含む行だけ残す）はやめた。エージェントが
「11月の大阪のハッカソン」を期間と地域に分けるのに、行側で同じ文字列を要求すると
結果が消える。チップ（すべて / 締切間近 / オンライン / 要確認）は残す。

## 検証

- Vertex（`gemini-3.8-flash`）: 「京都か大阪で10月にある学生も参加できる生成AIのハッカソン」→
  地域 京都・大阪 / 期間 10/1〜10/31 / 語 学生・生成AI に解釈、5 件 → 3 件に絞り、理由つきで
  「Gemini API ハッカソン 2026 / 大阪で10月開催のGeminiハッカソンです。」が先頭。2 呼び出し
- `tests/test_pool_search.py`: 相対期間の決定論的な変換、規則ベースの解釈、
  モデル出力の検証（選択肢外の地域・壊れた日付・命令様の語・存在しない id・数値でない
  関連度を捨てる）、命令様の問いかけの拒否、API の契約適合とセッション更新

## 限界

- 解釈の地域は既知の選択肢だけ。「滋賀」は捨てられて現在の関心条件が残る
- 関連度は上位 20 件だけに付く。プールが大きくなれば絞り込みの精度が効く
- Grounding 探索を裏口として残しているが、UI からは呼べない。デモで Web 収集の
  動きを見せたいときは設定画面から最新の収集 Run を見せる（未実装、次の課題）
